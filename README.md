# Tokenizer Comparison Tutorial

**Author:** Dr Giorgio Roffo  
**Year:** 2025-2026

A hands-on tutorial for students learning Large Language Models (LLMs) that demonstrates how different language models tokenize text. This tutorial is designed to run locally on your machine, helping you understand the fundamental concepts of tokenization and how different models process text.

## Why Understanding Tokenizers Matters

Tokenizers are the first step in processing text for language models. They convert human-readable text into numerical tokens that models can understand. Different models use different tokenization strategies, which affects:

- How text is split into tokens
- The vocabulary size
- Special tokens used (e.g., start/end tokens)
- Token IDs assigned to the same words
- Overall model behavior and efficiency

Understanding tokenization is crucial for:
- **Debugging model outputs** - Knowing how text is tokenized helps understand model behavior
- **Prompt engineering** - Different tokenization affects how prompts are interpreted
- **Model comparison** - Comparing tokenizers reveals architectural differences
- **Efficiency** - Token count affects computational cost and context window usage

## What This Tutorial Teaches

This script compares tokenizers from four popular language models:

- **Llama 3.1** (Meta) - Uses `PreTrainedTokenizerFast`
- **Phi-4** (Microsoft) - Uses `GPT2TokenizerFast`
- **Deepseek** - Uses `LlamaTokenizerFast`
- **Qwen** - Uses `Qwen2TokenizerFast`

You'll learn:
- How to load tokenizers from different models
- How to encode text into tokens and token IDs
- How different tokenizers handle the same text differently
- What special tokens each model uses
- How to compare tokenization strategies side-by-side

- Python 3.8 or higher

1. **Clone the repository:**


   **Important:** Make sure your token has **write permissions** enabled.

## Key Concepts Explained

### What is Tokenization?

Tokenization is the process of breaking text into smaller units (tokens) that models can process. For example:

- **Word-level**: "Hello world" → ["Hello", "world"]
- **Subword-level**: "Hello world" → ["Hello", "Ġworld"] (with space marker)
- **Character-level**: "Hello" → ["H", "e", "l", "l", "o"]

Most modern LLMs use **subword tokenization** (like BPE or SentencePiece), which balances vocabulary size with the ability to handle new words.

### Special Tokens

Special tokens have specific meanings:
- `bos_token` (beginning of sequence) - Marks the start of text
- `eos_token` (end of sequence) - Marks the end of text
- `pad_token` - Used for padding sequences to the same length
- `unk_token` - Represents unknown/out-of-vocabulary words

### Why Different Tokenizers?

Different models use different tokenizers because:
- **Architecture requirements** - Some architectures need specific token formats
- **Training data** - Tokenizers are trained on specific datasets
- **Language support** - Some tokenizers handle multilingual text better
- **Efficiency** - Vocabulary size affects model size and speed

## Troubleshooting

### "GatedRepoError" or "401 Client Error"

**Solution:** You need to request access to gated models (especially Llama). See the "Model Access Requirements" section above.

### "ModuleNotFoundError: No module named 'transformers'"

**Solution:** Install dependencies: `pip install transformers python-dotenv`

### "HF_TOKEN not found"

**Solution:** Create a `.env` file with your HuggingFace token. See the Setup section.

### Model download is slow

**Solution:** Tokenizers are relatively small (~few MB), but first-time download may take a minute. Subsequent runs use cached tokenizers.
